# Хостинг бота на Cloudflare Workers + D1 (безкоштовно, без картки)

## Як усе буде влаштовано

```
GitHub Actions (о 20:05 і 08:05 за Києвом)          Cloudflare Worker (24/7, безкоштовно)
  оновлює дані тривог і рахує прогноз для 104   ──►   /ingest: приймає прогноз, кладе в базу D1
  районів (pandas, моделі: те, що вже є)               /telegram: відповідає на кнопки й команди
                                                       розклад кожні 5 хв: розсилає підписникам
                                                       (до 40 повідомлень за раз: ліміт 50 запитів)
                                    Telegram ◄──────── webhook: Telegram сам надсилає оновлення на Worker
```

**Чому так.** Cloudflare безкоштовний і без картки, але pandas і моделі там не запускаються. Тому важкий прогноз рахує GitHub Actions двічі на день, а Worker лише зберігає готові цифри і спілкується з людьми.

**Правила GitHub.** Actions не можна використовувати як «частину serverless-застосунку». Щоденний перерахунок результатів самого проєкту я вважаю дозволеним: так само щодня оновлюється датасет Vadimkin. Але це моя інтерпретація, а не цитата правил. Якщо хочеш нуль ризику, прогноз можна рахувати на ноутбуці й надсилати на Worker тією ж командою.

## Крок за кроком

### Частина А · робиш ти (~10 хв, без картки)
1. **Акаунт:** dash.cloudflare.com/sign-up → email і пароль → підтверди лист. Тариф **Free**, картку не вводиш.
2. **Інструменти на Mac**, один раз:
   ```bash
   brew install uv
   ```
3. **Вхід у Cloudflare з терміналу:** відкриється браузер, натисни «Allow».
   ```bash
   npx wrangler login
   ```
   Пароль я не вводжу і не бачу. На ноутбуці лишається лише токен доступу wrangler.

### Частина Б · роблю я (код, ~2–3 год)
4. **Worker на Python** у `deploy/cloudflare/worker/`:
   - ті самі тексти, кнопки й правила, що зараз (ui, router);
   - база D1 замість SQLite;
   - розклад кожні 5 хв з перевіркою часу за Києвом (перехід на зимовий час 25.10 враховується);
   - захист: webhook приймається лише із секретним заголовком Telegram (`X-Telegram-Bot-Api-Secret-Token`), а `/ingest` лише з нашим секретом.
5. **Схема бази D1** (`schema.sql`): підписники, райони, журнал відправок (без дублів), прогнози.
6. **GitHub Actions** `.github/workflows/forecast.yml`: двічі на день оновлює дані, рахує прогноз і надсилає JSON на `/ingest`.
7. **Тести:** вся логіка перевіряється локально (`pywrangler dev`) з фейковим Telegram, як зараз.

**Що перевіряю під час збирання (не знаю напевно):**
- **Ліміт процесорного часу.** На Free це 10 мс CPU на запит, а сторонні джерела називають і 30 мс. Якщо Python не вкладеться, той самий Worker напишу на JavaScript: логіка проста, і це надійніший варіант.
- **Точний синтаксис** обробника розкладу і викликів D1 з Python: офіційна сторінка Python Workers його не показує.

### Частина В · запуск (команди дам готовими, ~10 хв)
8. **Створити базу:**
   ```bash
   uv run pywrangler d1 create shkilnyi-ranok
   ```
   Її id я впишу в конфіг.
9. **Створити таблиці:**
   ```bash
   npx wrangler d1 execute shkilnyi-ranok --remote --file deploy/cloudflare/schema.sql
   ```
10. **Секрети.** Їх вводиш ти, ввід прихований, і в git вони не потрапляють:
    ```bash
    npx wrangler secret put TELEGRAM_BOT_TOKEN
    ```
    Ще два секрети, `WEBHOOK_SECRET` та `INGEST_SECRET`, я згенерую випадково і передам тобі командою.
11. **Розгорнути:**
    ```bash
    uv run pywrangler deploy
    ```
    Отримаєш адресу `https://shkilnyi-ranok.<твій-піддомен>.workers.dev`.
12. **Сказати Telegram, куди слати оновлення (webhook).** Команду дам готову. Вона бере токен зі змінної середовища, тож він не потрапляє в історію.
13. **Секрети для GitHub Actions** (адреса `/ingest` і `INGEST_SECRET`): ставлю я через `gh secret set`.
14. **Зупинити бота на ноутбуці.** З webhook старий спосіб (`getUpdates`) уже не працює, тож двох копій не буде.

### Частина Г · перевірки після запуску
15. У Telegram: `/start` → область → район → «Готово». Відповідь має прийти за 1–2 с.
16. Логи наживо:
    ```bash
    npx wrangler tail
    ```
17. Запустити прогноз вручну й переконатися, що він дійшов у базу:
    ```bash
    gh workflow run forecast.yml
    ```
18. О 20:05 має прийти вечірній прогноз. Журнал відправок показує, кому пішло, а кого пропущено.
19. Через 2 дні перевірити, що безкоштовні ліміти не наближаються до межі (Cloudflare dashboard → Workers → Metrics).

## Ліміти Free (на 12.10.2026; перевір на сторінці Cloudflare)
| Що | Ліміт | Що це означає для нас |
|---|---|---|
| Запити | 100 000 / день | з великим запасом |
| Запити назовні за один запуск | 50 | розсилка по 40 за раз кожні 5 хв, тобто до ~480 повідомлень на годину |
| Розклади | 5 на акаунт | нам вистачить одного (кожні 5 хв) |
| D1 | денні ліміти читань і записів; з 01.09.2026 при перевищенні запити падають до півночі UTC | для сотень підписників далеко до межі |
| CPU | 10 мс (у сторонніх джерелах і 30 мс) | головний ризик, див. вище |
