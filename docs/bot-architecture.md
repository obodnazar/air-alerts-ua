# Бот «Шкільний ранок»: як він влаштований

## Як роблять такі боти (і що ми з цього беремо)

| Практика | Звідки | У нас |
|---|---|---|
| Оновлення бот отримує або через **long polling** (`getUpdates`), або через **webhook** (потрібен HTTPS-сервер). Обидва способи разом не працюють | core.telegram.org/bots/faq | long polling: бот працює з ноутбука чи будь-якого сервера без домену й сертифіката |
| **Ліміти:** ≤1 повідомлення на секунду в один чат, ≈30 на секунду всім разом, інакше помилка 429 | там само | розсилка з паузою, на 429 бот чекає `retry_after` і повторює |
| Якщо користувач заблокував бота, Telegram повертає 403 | Bot API | підписка вимикається, бот не падає |
| Кнопки під повідомленням (**inline keyboard**), натиск приходить як `callback_query`. У кнопці можна передати лише 64 байти | Bot API | у кнопках лише номери (`ob:3`, `u:57`), а не назви українською |
| Популярні бібліотеки: python-telegram-bot, aiogram | — | **чистий HTTP через стандартну бібліотеку**: жодних нових залежностей, а кожну частину можна протестувати без Telegram |
| Дані користувачів | — | зберігаємо лише `chat_id` і обраний район (SQLite), більше нічого |

## Сценарій користувача

```
/start ─► «Оберіть область» [24 кнопки] ─► «Оберіть район» [кнопки районів] ─► ✅ підписка
   або просто напишіть назву: «Біла Церква» ─► [Білоцерківський район] ─► ✅
/settings ─► контрольна точка школи [09 10 11 12] · ранкове повідомлення [завжди | лише якщо тривога]
/now  ─► прогноз на завтра зараз          /stop ─► відписатися
20:00 ─► прогноз на ранок для мого району (з контрольною точкою, яку я обрав)
08:05 ─► якщо о 08:00 тривога: колір, скільки триває, шанс відбою до моєї контрольної точки, порада
         ⚠️ банер, якщо в новинах перемир'я або попередження про масовану атаку
```

## Будова

```
src/airalerts/botapp/
  catalog.py    райони (104), області → райони, пошук міста: громада → район (точка в межах району)
  store.py      SQLite: підписники, налаштування, журнал відправок (одне повідомлення на день, без дублів)
  forecasts.py  раз на вечір/ранок рахує прогноз для ВСІХ районів і кешує; бот лише читає кеш
  banner.py     читає останні пости @lachentyt, @kpszsu, @V_Zelenskiy_official → банер
                («не підтверджено», якщо є лише в «Лачені»; «підтверджено», якщо є в офіційному джерелі)
  texts.py      тексти повідомлень (без AI, лише шаблон)
  keyboards.py  кнопки
  router.py     обробка команд і кнопок → список дій (чиста логіка, тестується без мережі)
  telegram.py   HTTP до Bot API: повтор на 429, вимкнення підписки на 403
  main.py       цикл: getUpdates + розклад (19:50 прорахунок, 20:00 відправка, 08:02 оновлення, 08:05 відправка)
```

**Чому прогноз рахується один раз на всі райони.** Модель працює ~1 хв. Якщо рахувати на кожного користувача, 100 людей чекали б 100 хв. Кеш дає відповідь за мілісекунди.

## Перевірки
- **Тести без мережі:** каталог, пошук міст, кнопки, роутер, тексти, журнал відправок (без дублів), повтор на 429, логіка банера.
- **«Симуляція дня»:** фейковий Telegram, 3 підписники, вечірня і ранкова розсилка. Перевіряємо, що кожен отримав своє, а повторний запуск не шле дублів.
- **Живий запуск:** з токеном, який вводить Назар.

## Кастомізація (12.10, друга версія)
| Налаштування | Варіанти | Навіщо |
|---|---|---|
| Райони | до 3 | діти в різних школах, робота й дім; усе приходить одним повідомленням |
| Контрольна точка | 09 / 10 / 11 / 12 | кожна школа обирає свою за правилом МОН; від неї залежить шанс відбою «до» |
| Час вечірнього прогнозу | 20:00 / 20:30 / 21:00 | прогноз рахується один раз о 19:45, а доставляється, коли зручно |
| Стиль порад | обережний / збалансований / сміливий | наскільки охоче радити дистанційний ранок; «збалансований» = пороги з валідації |
| Ранкове повідомлення | лише при тривозі / щоранку | менше шуму або повна картина |
| Банер новин | увімк. / вимк. | хтось не хоче політики в шкільному боті |
| Пауза | 1 / 2 тижні / відновити | канікули, хвороба |

## Безпека і надійність
- **Токен:** лише змінна середовища або root-файл на сервері (`/etc/shkilnyi-ranok.env`, 600). У репо його немає, і в логах він не друкується.
- **Персональні дані:** лише `chat_id` і налаштування. Файл лежить у `data/bot/` і ігнорується git.
- **Дані з кнопок можна підробити,** тому кожне значення парситься безпечно і звіряється з білим списком (`Store.set`). SQL лише з параметрами, назва поля теж із білого списку. Тест надсилає 14 підроблених варіантів (`cp:99`, SQL-ін'єкцію, `u:-1`…), і стан не змінюється.
- **Спам:** не більше 8 дій на чат за 10 с, решта відкидається.
- **Ізоляція розсилки:** помилка на одному підписнику не зупиняє інших. Хто заблокував бота (403), того вимикаємо. На 429 бот чекає `retry_after`.
- **Без дублів:** журнал відправок у SQLite, тож перезапуск посеред розсилки нічого не повторює.
- **Сервер:** systemd з `NoNewPrivileges`, `ProtectSystem=full`, `MemoryMax`, окремий системний користувач без shell.
