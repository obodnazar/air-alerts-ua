# 10. UX і візуальний стиль бота «Шкільний ранок»

Дата дослідження: 12.10.2026. Метод: WebFetch/WebSearch (~28 звернень). Мова: українська.

Позначки надійності:
- **[підтв.]** — прочитано на офіційній сторінці Telegram (core.telegram.org) у цьому дослідженні.
- **[3-тє джерело]** — зі сторонньої сторінки або зі стислого переказу пошуку, офіційно не підтверджено.
- **[не перевірено]** — відомо мені «з пам'яті» або не вдалося знайти; перевірити перед використанням.
- **[рекомендація]** — моя пропозиція, а не факт.

Важливе застереження про метод: WebFetch віддає короткий переказ сторінки, а Bot API-довідник має ~580 000 символів, тому поля кнопок і форматування я читав шматками по 100 000 символів. Версії Bot API 10.x (травень–серпень 2026) лежать після моєї власної бази знань, тому вони спираються тільки на changelog; перед кодуванням перевірте поля у bots/api та підтримку у вашій бібліотеці (aiogram / python-telegram-bot).

## 1. Можливості платформи Telegram

### 1.1 Версії Bot API 2025–2026 (changelog)

| Версія | Дата | Що важливо для нас |

| 9.1 | 03.07.2025 | Чекліст-повідомлення, `hideKeyboard` для Mini Apps |
| 9.3 | 31.12.2025 | `sendMessageDraft` (потокові чернетки), `message_effect_id` при forward/copy |
| 9.4 | 09.02.2026 | **Поле `style` у кнопок** (колір), **`icon_custom_emoji_id`** на кнопках, custom emoji у повідомленнях бота (за умови Premium у власника бота) |
| 9.5 | 01.03.2026 | `sendMessageDraft` доступний усім ботам; сутність `date_time` (форматована дата/час); `iconCustomEmojiId` у BottomButton Mini App |

Які саме з 10.x нам потрібні? Практично жодна: «Шкільний ранок» — це короткі текстові повідомлення в приваті. Rich Messages (10.1+) можуть згодитися для 20:00-картки, але це нове й залежить від клієнтів і бібліотеки; не закладайте на них критичний шлях [рекомендація].

### 1.2 Форматування повідомлень

Джерело: https://core.telegram.org/bots/api#formatting-options та sendMessage [підтв.]
- Ліміт тексту: 1–4096 символів після розбору entities.
- HTML-теги: `<b> <i> <u> <s> <code> <pre> <a> <blockquote> <blockquote expandable> <tg-spoiler> <tg-emoji> <tg-time>`; MarkdownV2 теж підтримує `||spoiler||`. Blockquote і expandable blockquote не можна вкладати одне в одне.
- `<tg-time>` (сутність `date_time`, Bot API 9.5): клієнт сам показує час у часовому поясі читача. Корисно для «відбій до 09:30» — без плутанини поясів [підтв. з changelog; формат рядка `r|w?[dD]?[tT]?` з довідника].
- `<tg-emoji>`/custom emoji: лише коли бот придбав додаткові юзернейми на Fragment або у повідомленнях, надісланих ботом безпосередньо в приват/групи, якщо **власник бота має Telegram Premium** [підтв.]. Тобто для читачів Premium не потрібен, але вам (власнику) потрібен.
- Спойлер (`tg-spoiler`) — не використовувати для загроз; для безпекових повідомлень приховування інформації контрпродуктивне [рекомендація]. Розгортувана цитата доречна для «Чому такий відсоток?» — пояснення за запитом, а не в основному тексті [рекомендація].

Порада по дизайну тексту: мобільний екран вміщує 6–8 рядків без прокрутки — основний висновок («Імовірність тривоги о 08:00: 12%») у першому рядку, деталі — під розгортувану цитату [рекомендація].

### 1.3 Ефекти повідомлень (`message_effect_id`)

- `message_effect_id`: «for private chats only» [підтв.: https://core.telegram.org/bots/api#sendmessage — прочитано у випуску довідника].
- Список ефектів у Bot API-довіднику відсутній. Загальна MTProto-документація каже, що ідентифікатори отримують методом `messages.getAvailableEffects`, а список слід перевіряти не частіше ніж раз на годину; кожен запис має `emoticon` і прапорець «потрібен Premium» [підтв.: https://core.telegram.org/api/effects, за переказом пошуку].
- Конкретні числові ID (я пам'ятаю 5046509860389126442 для конфетті, 5104841245755180586 для вогню) — **[не перевірено]**, не покладайтеся на них без тесту в приватному чаті.
- Рекомендація: **не використовувати ефекти взагалі** для сповіщень про тривогу. Конфетті/вогонь на повідомленні про ризик — це саме «розвага навколо загрози». Максимум — тихий ефект при завершенні онбордингу, але й це необов'язково.

### 1.4 Реакції

- `setMessageReaction`: боти без Premium — не більше **однієї реакції на повідомлення**; платні реакції недоступні ботам [підтв.: https://core.telegram.org/bots/api#setmessagereaction].
- Патерн: реакція 👌/👀 на текст користувача («Суми») як тихе підтвердження «побачив», перед редагуванням меню — менше шуму, ніж окреме повідомлення [рекомендація].

### 1.5 Анімації, стікери, chat actions

- `sendAnimation`, `sendSticker` існують [підтв., розділ у довіднику]; у пакеті я не знайшов нових обмежень. Для теми тривог: жодних анімованих стікерів зі «сполохами»; допустима тиха статична картинка-заставка (небо на світанку) [рекомендація].
- `sendChatAction`: статус діє «5 seconds or less» [підтв.]. Корисно, якщо відповідь тягнеться (розрахунок ймовірності) — але це тривіальна операція, «typing…» краще показувати лише коли справді є затримка >1 с [рекомендація].
- `sendMessageDraft` (9.3; усім ботам з 9.5): тимчасове превʼю ~30 с, порожній текст показує «Thinking…», потім треба `sendMessage` [підтв.]. Для нашого бота потоковий вивід не потрібен; він для LLM-відповідей.
- `answerCallbackQuery`: текст до 200 символів; `show_alert` за замовчуванням false [підтв.]. Завжди відповідайте, інакше на кнопці крутиться «годинник».

### 1.6 Інлайн-клавіатури та кнопки

Джерело: https://core.telegram.org/bots/api#inlinekeyboardbutton, #keyboardbutton, #replykeyboardmarkup [підтв.]
- `callback_data`: **1–64 байти**. Кирилиця в UTF-8 = 2 байти на літеру → не кладіть назви; тільки короткі коди (`r:123`, `cp:10`) [підтв. + моя арифметика].
- `style` (Bot API 9.4+) на KeyboardButton та InlineKeyboardButton: «`danger` (red), `success` (green) or `primary` (blue)»; без значення — стиль залежить від застосунку [підтв.]. Рекомендація: максимум `primary` для головної дії, **ніколи не червоний/зелений для рівнів ризику** (дальтонізм + «світлофор» поверх реальної загрози). `danger` — лише для «Видалити мої дані».
- `icon_custom_emoji_id` на кнопках: працює за тієї ж умови (Premium власника), на практиці одна іконка на кнопку [підтв. changelog 9.4]. Можна обійтись звичайним Unicode-емодзі на початку мітки.
- `copy_text` — кнопка «копіює текст у буфер» [підтв.]; `disabled` (Bot API 10.3) — вимкнена кнопка [підтв.]. Корисно для «поточний вибір» без дій.
- Reply-клавіатура: `input_field_placeholder` 1–64 символи, `is_persistent`, `resize_keyboard` [підтв.]. Приклад placeholder: «Напишіть назву міста або села».
- Кількість кнопок і обрізання підписів: **офіційних цифр у довіднику я не знайшов**. Сторонні джерела: до 8 у ряду та 100 всього [3-тє джерело: https://getclawkit.com/skills/official-ivangdavila-telegram-bot-api], обрізання посередині після ~35 символів [3-тє джерело: https://docs.connectiveone.io/en/scenariodialog/explanation/inline-keyboard.md]; інша платформа твердить 15 символів і перенесення [3-тє джерело: https://help.just-ai.com/1.12.2/docs/en/dsl/reaction-tags/inlineButtons]. Джерела суперечать; клієнти (iOS/Android/Desktop) обрізають по-різному.
  Практичне правило для нас [рекомендація, перевірити на вузькому Android ~360 dp]: підпис у кнопці ≤ 14–16 символів, якщо кнопок 2 у ряду; ≤ 28 символів, якщо одна кнопка в ряду; назви районів — по одній у ряду (є «Нікопольський район», «Кам'янсько-Дніпровський район»), але **без слова «район»** у мітці, коли контекст (заголовок повідомлення) уже каже «Оберіть район». Довгі назви скорочувати суфіксом: «Кам'янсько-Дніпр.» гірше за чесне «Кам'янсько-Дніпровський» в одному ряду.

### 1.7 Профіль бота

Джерела: https://core.telegram.org/bots/features, https://core.telegram.org/bots/api (setMy*) [підтв.]
- Юзернейм: 5–32 символи, латиниця/цифри/підкреслення, закінчується на `bot`.
- Імʼя (`setMyName`): до 64 символів; опис (`setMyDescription`) до 512; short description («про бота») до 120 символів; описи можна задавати по мовах (`language_code`) [підтв.].
- Description picture (фото/відео у блоці «Що вміє цей бот?»): задається в BotFather; офіційних розмірів не наведено. Сторонні гайди: 640×360 для зображення, GIF 320×180 / 640×360 / 960×540 [3-тє джерело: https://sendpulse.com/knowledge-base/chatbot/telegram/description].
- Аватар (`/setuserpic`): офіційних розмірів не знайдено; сторонні гайди — квадрат 500×500 (мінімум 300×300) [3-тє джерело: https://smartsender.io/knowledgebase/how-to-set-an-avatar-for-a-telegram-bot/]. Робіть 640×640, спрощений силует — на малому розмірі читаються лише 1–2 форми.
- Команди: до 100, до 32 символів; глобальні `/start`, `/help`, `/settings` [підтв.].
- Меню-кнопка: `setChatMenuButton` (за замовчуванням `MenuButtonDefault` — список команд, або `web_app`-кнопка) [підтв. + https://core.telegram.org/bots/webapps]. Для приватного чату покажіть команди `/settings`, `/pause`, `/help`.
- Deep link: `https://t.me/<bot>?start=<param>`, параметр до 64 символів `A–Z a–z 0–9 _ -` [підтв.] — придатний для QR на дошці в школі: `?start=school_123`.

### 1.8 Ліміти розсилки та тихі повідомлення

- Офіційна сторінка features про розсилки не містить конкретних цифр [підтв., відсутність]. Загальновідомі ~30 повідомлень/с на всю розсилку та 1/с на чат — на faq-сторінці Telegram; **[не перевірено в цій сесії]**: https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this. Для 20:00-розсилки заплануйте розмазування в чергу з перевіркою 429 `retry_after`.
- `disable_notification` у sendMessage [не перевірено в цій сесії, але це давній стандартний параметр]: для 20:00-прогнозу розумно слати зі звуком лише тим, хто не вимкнув; для «фонових» повідомлень — без звуку.

### 1.9 Mini Apps (Web Apps)

Основне джерело: https://core.telegram.org/bots/webapps [підтв.]
- **themeParams**: кольори теми користувача (`#RRGGBB`), CSS-змінні `var(--tg-theme-bg-color)` тощо; `var(--tg-color-scheme)` — light/dark. Додаткові кольори: `secondary_bg_color` (6.1), header/accent/section/subtitle/destructive (7.0), `section_separator_color` (7.6), `bottom_bar_bg_color` (7.10).
- **HapticFeedback** (6.1): impact (light/medium/heavy/rigid/soft), notification (error/success/warning), selectionChanged.
- **MainButton / SecondaryButton**: перейменовано в BottomButton у 7.10; підтримують індикатор прогресу; `iconCustomEmojiId` з 9.5.
- **CloudStorage** (6.9): до 1024 ключів на користувача; ключ 1–128 символів `A–Za–z0–9_-`; значення 0–4096 символів. **DeviceStorage** (9.0): 5 МБ на бота на користувача. **SecureStorage** (9.0): до 10 елементів (Keychain/Keystore).
- **Fullscreen** (8.0): `requestFullscreen`/`exitFullscreen`. **addToHomeScreen** / `checkHomeScreenStatus` (8.0).
- **BackButton** (6.1), **SettingsButton** (7.0) — пункт «Налаштування» у меню Mini App.
- Запуск: меню-кнопка (`setChatMenuButton`, 6.0), web_app-кнопка клавіатури (`sendData` до 4096 байт, лише приват), інлайн-кнопка, пряме посилання `t.me/<bot>/<app>`, Main Mini App `t.me/<bot>?startapp` з `mode=compact` (півекрана).
- Гайдлайни (стисло з довідника): mobile-first; плавні анімації ~60 fps; підписувати поля та зображення; поважати safe area / content safe area; на слабких Android (User-Agent містить performance class LOW/AVERAGE/HIGH) зменшити анімацію.
- **Безпека (Bot API 10.2):** з **20.07.2026** автоматично заборонено виклики методів Mini App з origin, відмінних від домену Mini App; відмовитись можна в BotFather Mini App, але тоді власник відповідає за відсутність посилань на сторонні сайти [підтв. changelog]. Для нас: Mini App має бути на одному власному домені й не вбудовувати чужі iframe.
- Хостинг: Mini App — статичний HTML/JS на HTTPS. GitHub Pages підходить: сторонні гайди описують URL `https://<user>.github.io/<repo>/` і вставку його в BotFather → Bot Settings → Menu Button [3-тє джерело: https://docs.ton.org/v3/guidelines/dapps/tma/tutorials/step-by-step-guide; https://github.com/killedCode/vanilla-js-boilerplate]. Telegram сам нічого не хостить — «must be hosted somewhere publicly accessible». Сервер потрібен тільки для збереження налаштувань і перевірки `initData`; статика на Pages без бекенду не може безпечно ідентифікувати користувача [3-тє джерело; логіка перевірки initData описана в довіднику, у прочитаному фрагменті її не було]. Приватні репозиторії на безкоштовному тарифі GitHub Pages — **[не перевірено]**; використовуйте публічний репозиторій без секретів.
- Тестове середовище Telegram — окреме, з окремим акаунтом і ботом [підтв.].

Висновок щодо Mini App [рекомендація]: головна проблема — вибір області → району та налаштування (3 райони, контрольна точка, час, стиль, пауза). Mini App дає пошук по списку, великі рядки на повну ширину, перемикачі — це вирішує обрізання назв остаточно. Але робити його **додатковим, а не єдиним шляхом**: чат-флоу з кнопками лишається (швидкий старт ≤3 тапи), а «Розширені налаштування» відкривають Mini App. Не зберігати налаштування в CloudStorage як єдине джерело — тримати на сервері, бо розсилка о 20:00 їх читає.

## 2. Що хвалять і на що скаржаться в UX Telegram-ботів

Чесно про покриття: Reddit (r/TelegramBots, r/Telegram, r/UXDesign) через інструмент пошуку **не знайшовся** жодного прямого треду; стаття з Хабру (https://habr.com/ru/articles/1019178) повернула 403; vc.ru через помилку сертифіката не відкрилась, її зміст — з переказу пошуку. Нижче — лише те, що вдалося підтвердити, плюс чітко позначені мої висновки.

Знайдене:
1. **Редагуйте, а не спамте.** Telegram у анонсі Bots 2.0 описує бота @music, який змінює власне повідомлення під час листання результатів, без нових повідомлень: https://telegram.org/blog/bots-2-0 [3-тє джерело через пошук]. `editMessageText`/`editMessageReplyMarkup` — стандартний метод; бот може видаляти повідомлення в приваті лише в межах 48 годин, тому багатокроковий вибір краще будувати на редагуванні [3-тє джерело].
2. **Не більше 3 тапів до результату.** Стаття vc.ru 2026 року: якщо потрібно натискати кнопки більше трьох разів, сценарій програв, складне — у Mini App [3-тє джерело, переказ: https://vc.ru/2675038-telegram-boty-v-2026-perestante-uzhe]. Це російськомовне джерело; використовуйте лише як ілюстрацію принципу.
3. **Мало емодзі.** Та ж стаття радить одну іконку, максимум дві на весь пост, без ряду 🔥⚡✅💡📌 у кожному рядку; дробити «простирадла» тексту; уникати канцеляриту («Шановний користувачу, для ініціалізації…») [3-тє джерело, переказ, там же].
4. **Скрипти онбордингу як розмова.** Hackernoon описує Mini App із діалогом «як чат» на основі одного JSON, з ефектом набору тексту, кнопками `goto` і аналітикою кожного кроку: https://hackernoon.com/3-telegram-ux-hacks-that-make-bots-feel-like-native-apps [прочитано]. Про редагування й chat actions там нічого немає.
5. **URL-кнопки вести напряму, без редиректу на ваш сервер** — зайвий крок затримує перехід; посилання формувати при створенні повідомлення (той самий Hackernoon, [прочитано]).
6. **Загальні помилки чат-ботів:** довгі відповіді подряд, загальне «Привіт» без підказки наступного кроку, довга реєстрація [3-тє джерело, переказ: https://venturebeat.com/business/5-common-mistakes-in-chatbot-design].
7. **Користувач у ботів хоче:** тихий режим, чітке «як вимкнути». Прямих джерел знайти не вдалося [не перевірено]; це стандартна пряма вимога до розсилок — тому в нас «пауза» і «ранкові повідомлення» мають бути видимі з першого меню.

Мої висновки для «Шкільного ранку» [рекомендація]:
- **Одне «живе» повідомлення-меню на екран**: усі переходи область → район → контрольна точка — це `editMessageText` з тим самим message_id. Повідомлення користувача (введений населений пункт) — позначати реакцією й не відповідати новим бабблом.
- **Онбординг ≤3 тапи**: (1) /start → «Ваша область» (сітка по 2) → (2) район → (3) «Готово» зі значеннями за замовчуванням (контрольна точка 10:00 [значення з вашого дизайну], доставка 20:00). Решта налаштувань — після першого прогнозу, не до нього.
- **Reply vs inline**: постійна reply-клавіатура лише з 3–4 кнопками («Сьогодні», «Мої райони», «Налаштування», «Пауза»); усі вибори — inline. Постійна клавіатура зменшує екран, тож `resize_keyboard=true`.
- **Сповіщення без втоми**: один вечірній прогноз + 08:05 лише якщо тривога триває; тихі години й «не турбувати на вихідних/канікулах» — нативна опція; тижневе нагадування «ось що вам приходить; змінити?» замість мовчазної розсилки.
- **Тон для підлітків**: коротко, на «ти» за вибором «стиль порад», без сленгу й жартів, без вигуків про загрозу; приклади нижче.

Приклади (не складалися з джерел; тон — для обговорення):
- Вечір: «Завтра, Суми. 08:00 — тривога ймовірна на 12%. До 10:00 відбій ймовірний на 91%. Рекомендую піти в школу за планом.»
- Підліток: «Завтра вранці, скоріш за все, спокійно: 12% на тривогу о 08:00. Якщо щось зміниться — напишу о 08:05.»
- 08:05: «Зараз тривога у вашому районі. До контрольної точки 10:00 відбій імовірний на 78%. Дотримуйтесь вказівок школи.»

Заборонено [рекомендація]: стікери-«реакції» на загрозу, ефекти повідомлень, смайли-жарти, «серії днів», бали, значки за виконання — жодної гейміфікації небезпеки.

## 3. Візуальний стиль

### 3.1 Що відомо про подібні продукти
- **Карти тривог (alerts.in.ua)**: за оглядом Fakty (2024) легенда — червоний = тривога, сірий/чорний = немає тривоги, білий/світло-сірий = немає даних; жовтий належить іншому блоку посібника, не обовʼязково alerts.in.ua; карта оновлюється кожні ~25 с, джерелом є Telegram-канал «Повітряна тривога»: https://fakty.com.ua/en/ukraine/suspilstvo/20241201-onlajn-karta-povitryanyh-tryvog [3-тє джерело; сучасний вигляд сайту я не відкривав]. Походження сервісу — https://en.wikipedia.org/wiki/Alerts.in.ua [3-тє джерело].
- **Додаток «Повітряна тривога» (Ajax/Stfalcon, Мінцифри)** і eAlert: в App Store немає декларацій про доступність («developer has not yet indicated which accessibility features this app supports»): https://apps.apple.com/us/app/-/id1611955391 [3-тє джерело, самозвітність]. Тобто готового «зразка доступного дизайну» серед українських тривожних застосунків ми не знайшли.
- **Нова державна програма на базі «Дії»**: 04.09.2026 озвучено намір створити єдиний застосунок про тривоги і рух шахедів/ракет, деталей немає: https://fakty.com.ua/ua/ukraine/20260904-na-bazi-diyi-stvoryat-zastosunok-dlya-vidstezhennya-shahediv-i-raket-prem-yer/amp/ [3-тє джерело, переказ]. Для нас: позиціонувати бот як «прогноз і розклад для школи», а не як дублікат сирен.
- **Доступність кольорів**: WCAG 1.4.1 «Use of Color» (рівень A) — колір не може бути єдиним способом передати інформацію; техніки: текстові підписи, додаткові візуальні ознаки, колір + візерунок: https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html [підтв.]. Дослідження палітр для небезпек для людей із порушенням кольорового зору радить поєднувати палітру Meteoalarm із символами: https://scholarworks.montana.edu/handle/1/17428 [3-тє джерело, за фрагментом пошуку; сторінку відкрити не вдалося]. Оцінка 5–10% читачів мап із певним порушенням кольорового зору — з курсу Penn State: https://courses.ems.psu.edu/geog486/book/export/html/879 [3-тє джерело].

### 3.2 Пропозиція стилю [рекомендація]
- **Настрій**: «ніч → світанок» — переходить від темно-синього до теплого персикового/жовтого; це метафора «ранку», а не небезпеки.
- **Палітра** (приблизна; перевірити контраст ≥4.5:1 для тексту, ≥3:1 для значків):
  - ніч `#0E1B2E`, глибока синь `#1F3A5F`, туман `#8FA6C4`;
  - світанок `#F6B88C` (персик), `#FFE2A8` (світле золото);
  - текст на темному `#F2F5FA`; текст на світлому `#1B2433`.
  Червоний як фон повідомлення про ризик не вживати; для 08:05 «тривога триває» — нейтральний темно-синій заголовок + слово «Тривога» + значок ▲, без повного заливання червоним.
- **Рівні ризику, дружні до дальтонізму**: рівень = **слово + число + форма**, колір лише додатковий. Наприклад: «Низький — 12%» ○, «Помірний — 35%» ◐, «Високий — 70%» ●. Не покладатися лише на кольорові кружечки 🟢🟡🔴: червоне/зелене та жовте/оранжеве зливаються, а емодзі-кружки несуть тільки колір [рекомендація, на основі WCAG 1.4.1].
- **Іконографія**: лінійні, закруглені, 2 px штрих; сонце над горизонтом, дзвінок, шкільний рюкзак, годинник. Заборонені мотиви: ракети, вибухи, сирени у червоному, щити, радіолокатори.
- **Графіка в повідомленнях**: зображення-картки не мають альтернативного тексту в Telegram — тому основну інформацію давати **текстом**, картку лише як прикрасу, з тією ж інформацією в підписі [рекомендація].
- **Темна/світла тема**: у чаті колір тексту задає Telegram; власні кольори мають сенс лише в зображеннях (профіль, description picture) і в Mini App (через `themeParams`, не жорсткі hex).

## 4. Назви (8 кандидатів, наявність юзернейма не перевірялась)

Принципи: коротко, вимовно українською з латини, без військової лексики (alert, siren, shield, radar, guard), асоціація з ранком/спокоєм/школою. Юзернейм має закінчуватися на `bot`, 5–32 символи [підтв.: https://core.telegram.org/bots/features].

1. **Ranok** — «ранок» латиницею, читається без питань; прямий звʼязок із назвою «Шкільний ранок».
2. **Zorya** — «зоря»; тепла, поетична, знайома українцям, не про загрозу. Може бути зайнятою брендами — перевірте.
3. **Dawnly** — «dawn» + «-ly»; лагідне, «світанкове»; вимовляється «доунлі», легко для підлітків.
4. **Sunup** — «схід сонця»; дуже коротке, нейтральне, схоже на «Sunup bot».
5. **Before Bell** — «до дзвінка»; пояснює суть: прогноз до початку уроків; легко запамʼятати школярам.
6. **Clearly** — гра слів: «ясно/чітко» і «clear» (відбій) без згадки про тривогу; звучить спокійно.
7. **Lumo** — «світло» (lumen); два склади, зручне для аватара-лампи; без прив'язки до теми, тому потрібен гарний підпис «Шкільний ранок».
8. **Morning Compass** — «компас ранку»: орієнтир перед виходом із дому; чуттєво спокійне, але довше (юзернейм типу `MorningCompassBot` ≤32 — підходить).

Рекомендований формат [рекомендація]: імʼя в профілі — українською «Шкільний ранок» (до 64 символів), юзернейм — латиницею з 1–3; short description (≤120) — «Прогноз тривоги на 08:00 для вашого району — щовечора о 20:00».

## 5. Топ-10 дій

1. **Назви районів — по одній у ряду, без слова «район»**; пари кнопок лише для ≤14 символів; перевірити на 360-dp Android і iPhone SE.
2. **Редагувати те саме повідомлення** при кожному кроці, відповідати на `callback_query` завжди; реакцією підтверджувати введений текст.
3. **Онбординг: область → район → «Готово» зі значеннями за замовчуванням** (≤3 тапи), решту налаштувань запропонувати після першого прогнозу.
4. **Mini App лише для складного**: налаштування (до 3 районів, час, стиль, пауза) з пошуком; статика на GitHub Pages + мінімальний бекенд для initData; налаштування тримати на сервері.
5. **callback_data — короткі коди** (≤64 байти, кирилиця = 2 байти на літеру).
6. **Жодних ефектів, анімованих стікерів, спойлерів і «серій» у безпекових повідомленнях**; не використовувати червоний `style: danger` для ризику.
7. **Ризик = слово + число + форма**, колір додатково (WCAG 1.4.1); перший рядок повідомлення — головний висновок; деталі — у розгортуваній цитаті.
8. **Не спамити**: один вечірній прогноз + 08:05 лише при активній тривозі; тихі години, тижневе нагадування про налаштування, «Пауза» у першому меню; `<tg-time>` для часу відбою.
9. **Профіль**: імʼя «Шкільний ранок» (≤64), short description ≤120 з обіцянкою 08:00/20:00, description picture 640×360 у палітрі «ніч → світанок», аватар 640×640 із простим символом; команди `/settings`, `/pause`, `/help`; deep link `?start=school_…` для шкіл.
10. **Мовлення**: «ти» для підлітків за налаштуванням «стиль порад», «ви» для батьків і вчителів; без канцеляриту й без сленгу чи жартів про загрозу.

## 6. Що лишилось неперевіреним
- Точні ліміти кнопок у ряду та обрізання підписів по клієнтах (сторонні джерела суперечать).
- Числові `message_effect_id` (рекомендовано не використовувати).
- Розміри аватара та description picture в офіційних документах (є лише сторонні).
- Reddit-обговорення UX Telegram-ботів (інструмент пошуку їх не повернув).
- Поточний вигляд і легенда alerts.in.ua та застосунку «Повітряна тривога».
- Ліміти розсилки (faq), `disable_notification`, умови GitHub Pages для приватних репозиторіїв.
- Підтримка Bot API 9.4–10.3 у вашій бібліотеці та на старих клієнтах (кнопки зі `style` на клієнті, що їх не знає, — поведінка не документована в прочитаному).
